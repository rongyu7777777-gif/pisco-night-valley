这是 **14 镜 r2 静态修正提案和视频输入计划**，供在 PC 上继续审图、修正与制作。它不代表 14 张已获用户确认，也不代表 7 段新叙事视频已经生成。

交接仓库：[rongyu7777777-gif/pisco-night-valley](https://github.com/rongyu7777777-gif/pisco-night-valley)，独立分支 `codex/storyboard-r2-20261112`，工作目录 `production/2026-11-12/`。本交接不合并主分支、不创建 PR，也不发布或覆盖现有官网。

## 在 Windows 上打开

需要已安装 Git 与 Python。在 PowerShell 中执行：

```powershell
git clone --branch codex/storyboard-r2-20261112 --single-branch https://github.com/rongyu7777777-gif/pisco-night-valley.git pisco-night-valley-work
Set-Location pisco-night-valley-work
py -m http.server 4198 --bind 127.0.0.1
```

保持这个窗口运行，浏览器打开：

[http://127.0.0.1:4198/production/2026-11-12/review.html](http://127.0.0.1:4198/production/2026-11-12/review.html)

如果 Python 安装只提供 `python` 命令，把最后一行改为 `python -m http.server 4198 --bind 127.0.0.1`。结束预览按 `Ctrl+C`。本地地址只供当前电脑使用；GitHub 分支用于下载和交接素材。

## 下一步制作顺序

1. 先把 14 镜静帧及相邻镜头一起审完。角色、服装、门的结构与所有衔接道具应保持一致。存在多个候选或 QA 未解决项时，保留问题供用户选择，不把代理检查通过写成用户批准。
2. 优先验证 **01→02 开门**：首帧 `keyframes-r2/01-door-ajar.png`，尾帧 `keyframes-r2/02-door-open.png`。必须真实绑定两张图；不能再次只上传门缝图，让模型凭文字编造室内和人物。
3. 确认模型支持首尾帧、核对当前界面价格，并取得新的明确点数上限后，才提交这一段。先检查中间过程和尾帧，合格后继续其余六段。
4. 分别制作角色驻留环境循环，再接网页滚动、跨场景撕裂和独立文字层；最后检查前进、倒退、停在过场中途时的表现。

| 段落 | 严格对应的两镜 | 推进内容 |
|---|---|---|
| N01 | 01 门缝 → 02 推门进入 | 同一扇门由近乎关闭打开，显露原会所与原男主 |
| N02 | 03 私人会所 → 04 假面特写 | 黑金邀请函埋下目的地，沿同一假面发现古堡 |
| N03 | 05 吸血鬼古堡 → 06 海岸倒影 | 同一假面留在石栏，内侧显出下一站住宅 |
| N04 | 07 三位运动员 → 08 头盔特写 | 已出现的头盔、钥匙和机车引向车库 |
| N05 | 09 午夜车库 → 10 后视镜与地图 | 沿同一车镜和路线图发现白色拱城 |
| N06 | 11 精灵王庭 → 12 地图暖窗 | 同一地图展开，终点显出两位室友和三份晚餐 |
| N07 | 13 双女室友 → 14 留给你的座位 | 第三份餐具与开场同一邀请函完成呼应 |

7 对视频不自动覆盖 **02→03、04→05、06→07、08→09、10→11、12→13** 六处连接。02→03 是同一会所内的连续空间；其余五处以已出现的道具或倒影引导，并由网页撕裂揭露下一场。不得突然出现新的门或发光传送门。

每段 6 秒是源素材的动作范围，不是访问者的自动倒计时。叙事位置由滚动控制，可停、可逆。停留时雨、烛光、头发或呼吸可以继续微动，剧情动作不能自行推进。停在过场中途时不要跳回角色循环的起点。
